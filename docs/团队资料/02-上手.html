纹脉 · 本地运行指南

照这份手册，一个新队友 10 分钟内把主站跑起来，并能找到任何模块的代码。
① 环境要求 ② 克隆启动 ③ 配置 ④ 常用命令 ⑤ 目录结构 ⑥ 代码地图 ⑦ 数据同步机制

01环境要求

依赖要求
Node.js≥ 20.19（Vite 8 要求）；推荐 LTS
包管理器npm（默认）或 pnpm
Supabase 项目需要你自己建一个免费项目并填 key（见第 ③ 节），否则功能降级为本地 localStorage
StepFun API Key（可选）拍照识别 VLM 升级用；不填则降级为本地 pHash 匹配，核心功能不受影响

02克隆并启动

# 1. 克隆（SSH）
git clone git@github.com:oreno123/wenmai.git
# 或 HTTPS：git clone https://github.com/oreno123/wenmai.git

# 2. 安装依赖
npm install

# 3. 配置 .env.local（见下一节）
cp .env.example .env.local

# 4. 启动开发服务器
npm run dev
# → 浏览器打开 http://localhost:5173
启动后首页就能跑：抽卡、图鉴、拼图、3D 预览等纯前端模块无需任何后端配置即可体验。

03配置 .env.local

复制 .env.example，需要填两项（均可在 Supabase Dashboard → Settings → API 找到）：

VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key-here
# 拍照识别 VLM（可选，不填则本地 pHash）
VITE_STEPFUN_API_KEY=your_stepfun_api_key
本地已有 .env.local（已被 git 忽略，不会提交）。新队友首次克隆后需从 Supabase 项目复制自己的 key，或找队长要一份。

数据库建表（账号 + 广场）

Supabase 项目需要两张表：profiles（账号）与 works/likes（广场）。SQL 都有现成的：

  • 账号表 profiles：SQL 在仓库根目录 README.md 底部
  • 广场表 works / likes + 存储桶 + RLS：supabase/migrations/001_gallery.sql（整段粘贴到 SQL Editor 跑，跑完手动把自己设管理员，文件末尾有说明）

07账号数据同步机制

  • 登录瞬间：从 Supabase profiles 拉数据覆盖本地（云端优先）
  • 每次数据变更：1s debounce 推送到云端
  • 登出：停止推送，本地数据保留
  • 未登录：纯 localStorage，零侵入

坑：Supabase 默认开启邮箱验证，新注册账号必须去邮箱点确认链接才能登录。
